# 运动世界校园 · 一键跑步 v2.0（Windows 免安装版）

Windows 上一键完成当天校园跑的桌面工具。**下载即用**：不需要安装 Python，不需要模拟器，不需要 adb。

- 双击 `一键跑步.exe` → 手机号 + 密码登录 → 点「① 一键完成今天」→ 等待核验结果；
- 首次登录会弹一次滑块验证（在浏览器里拖一下，几秒），之后凭据本地加密保存，不必再登；
- 成绩由服务端核验（通常 5–15 分钟），工具自动轮询并在界面上显示最终判定。

> 本版为**编译后的可执行文件**，不含源码。程序内部对代码段做了加密与完整性校验，
> 直接从二进制反推实现逻辑的成本较高。

---

## 1. 运行要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| 磁盘 | 约 60 MB（单文件，运行时解压到临时目录） |
| 网络 | 能访问校园跑服务端、轨迹对象存储与验证码服务（校园网/公司网被拦时可在配置里设代理） |
| 权限 | 普通用户即可，无需管理员、无需 root |
| 运行时 | 无需安装 Python 或任何第三方库（已内置） |

首次运行会在 **exe 所在目录**生成 `config.json`、`credentials.bin`、`logs/`，因此**不要放在 `C:\Program Files`** 等只读目录。

## 2. 第一次使用（4 步）

```
① 把 一键跑步.exe 放到一个可写目录（例如 D:\Tools\一键跑步\）
② 双击运行 → 点「登录账号」→ 填手机号、密码 → 按提示在浏览器里拖一次滑块
③ 点「① 一键完成今天」，等待界面提示「已提交、核验中」
④ 点「② 核对数据」查看服务端回执（记录数、有效里程、判定信息）
```

图形界面之外也支持命令行（exe 带参数时会自动附一个控制台窗口）：

```bat
一键跑步.exe                            图形界面（默认）
一键跑步.exe login --phone 138xxxxxxxx   登录（密码交互输入，不回显）
一键跑步.exe login --phone 138xxxxxxxx --password 你的密码
一键跑步.exe status                     数据核对：今日记录 / 服务端判定 / 学期里程
一键跑步.exe verify                     同 status（只核对，不跑）
一键跑步.exe run                        跑一次（对时→规则→打卡点→轨迹→上传→结算→核验）
一键跑步.exe run --dry-run              只生成报文，不提交
一键跑步.exe run --stop-before-submit   只做到轨迹上传，不结算（排障用）
一键跑步.exe accounts                   列出本机已登录的账号
一键跑步.exe switch <手机号|uid>        切换当前账号
一键跑步.exe doctor                     环境自检（离线可加 --offline）
一键跑步.exe selftest                   离线全链路自测（不联网）
一键跑步.exe task install --time 06:10  注册每日计划任务
```

> 需要强制指定跑步参数时：`run --sport-type 6 --distance 3000 --duration 1100`

## 3. 每次数据都不一样，但都在合规区间内

工具会先读取学校规则（里程下限、速度区间、步频区间、有效时段），再在允许区间内**每次随机**生成一组自洽参数：

```
本次示例：2115 m / 790 s / 6'14"/km / 速度 2.68 m/s / 步频 177 步/分 / 步数 2335
```

| 项 | 配置键（`config.json` → `run`） | 默认 | 说明 |
|---|---|---|---|
| 里程 | `distance_range_m` | `[2000, 2200]` | 下限不低于学校规定的最小里程 |
| 配速 | `pace_range_sec_per_km` | `[360, 430]` | 与学校速度区间取交集 |
| 步频 | `cadence_range_spm` | `[166, 182]` | 与学校步频区间取交集 |
| 结束时刻 | `stop_offset_sec` | `[0, 25]` | 每次比"现在"提前 0–25 秒 |
| 固定里程/时长 | `distance_m` / `duration_sec` | `0`（关闭） | >0 时覆盖随机值，调试复现用 |

提交前会做自洽校验（速度 = 里程/时长、步频 = 步数×60/时长、步幅在人类区间、里程与时长不低于学校下限），任一项不通过就中止，不会发出不合规的报文。

`selftest` 内置 2×60 次抽样回归：宽松与严格两种校规下均为 0 次越界。

## 4. 多账号

```bat
一键跑步.exe login --phone 138xxxxxxxx --password 密码   :: 新增一次即自动切换
一键跑步.exe accounts                                  :: 列出本机所有账号
一键跑步.exe switch 139xxxxxxxx                        :: 按手机号或 uid 切换
一键跑步.exe run --account <uid>                       :: 仅本次使用指定账号
```

- 账号保存在 `credentials.bin` 的账本中，互不覆盖；界面顶部有「当前账号」下拉框；
- **每个账号一套独立设备指纹**（按手机号派生并落盘，之后不变），避免"同一台设备挂多号"的关联特征；老账号升级不会突然变成新设备；
- 运行状态（提交锁、核验结果、当日完成标记）也按账号隔离；
- 换账号后若服务端要求复核设备，会出现一次滑块或提示「需在官方 App 确认设备」，按提示操作即可。

## 5. 数据存放与隐私

| 文件 | 内容 | 保护方式 |
|---|---|---|
| `credentials.bin` | 登录令牌、uid、昵称、学校名 | **Windows DPAPI 加密**，仅当前 Windows 用户可解；换电脑拷过去也解不开 |
| `config.json` | 运行参数（不含密码） | 明文，可手工编辑 |
| `logs/` | 运行日志与诊断记录 | 密码不落盘，令牌只显示前缀 |

- 密码只在内存中用于一次登录，**不写入磁盘**；
- 换电脑或换 Windows 用户后，重新 `login` 一次即可，历史成绩都在服务端，不会丢失；
- 若担心日志含个人信息，删除 `logs/` 目录即可，不影响运行。

## 6. 排障

| 现象 | 处理 |
|---|---|
| 登录失败 `10003 / 10004 / 11307 / 10175` | 账号或密码不正确；忘记密码在官方 App 里用短信重置一次（30 秒），之后继续用密码登录 |
| `18001 / 18002` | 需先在官方 App 内完成设备绑定 / 确认换设备 |
| 滑块页面打不开 | 命令行会打印本地验证页地址，复制到浏览器手动打开；若公司网络拦截验证码域名，换网络或配置代理 |
| `401 头部信息不安全` | 令牌失效，重新 `login` |
| 提交后 `complete=false` | 未达最低里程/时长、配速越界或未过打卡点，看 `unCompleteReason` |
| 一直显示核验中 | 服务端异步核验，等 5–15 分钟后 `status` 复查，不要重复提交 |
| 提示「今天已完成」 | 当日有效里程额度已到，次日 06:00（UTC+8）后可再跑 |
| `doctor` 报网关不可达 | 换网络，或在 `config.json` 的 `net.proxy` 填写代理地址 |
| 提示「本校有多个跑步区域且未选定」 | 在 `config.json` 的 `run.run_area_id` 指定区域 id（日志会列出可选值） |
| 提示「服务端未下发打卡点」 | 该校区未开放或参数不符；请先在官方 App 内确认能正常起跑 |
| 提示人脸抽检 / 蓝牙打卡 | 该校启用了额外校验，本工具只提示不提供绕过 |

日志位置：`logs/sport-*.log`、`logs/login-debug-*.json`（密码与令牌已脱敏）。反馈问题时附上这两类文件即可定位。

## 7. 发布形态与加固说明

- 本版以**单文件可执行程序**分发，不含 `.py` 源码；
- 业务代码在打包前被编译为字节码并做**流密码加密 + HMAC-SHA256 完整性校验**，运行时只在内存中解密加载，不落盘；
- 引导层含反调试检测，检测到调试器时直接退出；
- 常规的「解包 → 字节码还原」路径无法直接得到业务逻辑；如需进一步降低风险，可自行用商业加壳工具二次处理。

> 客观说明：任何在本机运行的可执行文件都存在被逆向的可能，上述措施是**提高门槛**而非绝对防护。请勿把工具用于侵犯他人权益的场景。
